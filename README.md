# bakery- timing

“贝可的面包房”是一款以真实感烘焙流程包装专注计时的微信小程序原型。用户选择净专注时长，与英伦泰迪熊主厨贝可共同完成准备、揉制、醒发、整形和烘烤；只想专注时可隐藏经营信息，喜欢经营时则可处理订单、库存、图鉴、金币和装修。

![bakery- timing 首页视觉稿](assets/bakeco-home-visual.png)

## 当前能力

- 六档标准面包：30、60、90、120、150、180 分钟。
- 30～180 分钟自定义净专注时间，并向下匹配可制作面包；例如 75 分钟匹配 60 分钟红豆包。
- 专注倒计时、制作阶段、暂停资格、退出劝留和快速出炉预览。
- 店长台账、订单管理、麦子集市、图鉴和设置。
- 订单带入专注与本地演示金币购买。
- 奶油色、圆角、扁平蜡笔绘本风视觉方向。

## 小程序架构

当前仓库是无需 npm 构建即可运行的原生微信小程序原型。架构把微信页面代码和可迁移的业务规则分开，为后续 iOS / Android App 复用领域逻辑与服务端接口预留边界。

```text
project root
├── project.config.json          微信开发者工具项目配置
├── miniprogram/
│   ├── app.js                   全局演示状态
│   ├── app.json                 页面、窗口与三栏 TabBar 配置
│   ├── app.wxss                 全局奶油色设计系统
│   ├── assets/                  小程序运行图片
│   ├── config/                  默认数据、商品等版本化配置
│   ├── domain/                  与微信 UI 解耦的领域规则
│   │   ├── recipes.js           配方档位、向下匹配、快速出炉降档、阶段生成
│   │   └── focus-session.js     专注会话模型与时间格式化
│   ├── store/                   本地持久化与统一状态仓库
│   ├── services/                页面与领域/存储之间的用例接口
│   ├── custom-tab-bar/          三等分经营导航
│   └── pages/
│       ├── home/                面包房首页、时长选择与制作入口
│       ├── focus/               计时、阶段、暂停、放弃与抢救
│       ├── ledger/              日/周/月/年/全部店长台账
│       ├── orders/              零售、VIP、单次与周期订单
│       ├── market/              商品购买与演示金币扣除
│       ├── catalog/             成品、仓库、客户和成就入口
│       └── settings/            模式、目标、声音与权限设置
├── docs/PRD.md                  完整产品需求、经济模型与正式版架构
└── assets/                      高保真视觉原稿
```

### 1. 表现层

`miniprogram/pages` 只负责微信小程序页面生命周期、用户交互和状态展示。页面使用 WXML、WXSS 与原生 `Page` API，不依赖第三方 UI 框架。

首页负责选择净专注时长；订单页可以将预约任务带入专注；专注页展示当前制作阶段并处理暂停、退出确认和完成反馈。台账、集市、图鉴和设置属于可选经营层，不会在专注过程中主动打扰用户。

### 2. 领域层

`miniprogram/domain` 保存不依赖微信组件的核心规则：

- `matchRecipe(minutes)`：按实际时长向下匹配标准面包。
- `rescueRecipe(actualFocusMinutes)`：快速出炉时在实际时长档位基础上下降一档。
- `buildStages(recipe, targetMinutes)`：生成准备、揉制、醒发、整形休息和烘烤阶段。
- `createSession(...)`：创建专注会话数据。
- `formatClock(seconds)`：统一倒计时显示。

状态机使用绝对时间戳推进，而不是依赖 `setInterval` 累加秒数；逐秒定时器仅用于刷新画面。阶段按照各自真实分钟数消费，5 分钟整形休息不会计入净专注。

后续迁移 App 时，可以把这些函数移动到共享 TypeScript 包，而无需复制页面代码中的规则。

### 3. 计时状态机

```text
READY → FOCUSING ⇄ RECIPE_BREAK
              ⇅
         MANUAL_PAUSE
              ↓
          COMPLETED

FOCUSING / RECIPE_BREAK / MANUAL_PAUSE
              ↓
       ABANDON_CONFIRM
       ├── 继续制作 → FOCUSING
       ├── 依旧放弃 → ABANDONED
       └── 快速出炉 → RESCUED
```

- 用户选择的是净专注时间。
- 配方休息不计入净专注，会延长预计出炉时间。
- 快速整形会跳过休息，但不会减少净专注目标。
- 每完成 60 分钟净专注获得一次本次任务专用的 5 分钟暂停。
- 一个账号同时只能存在一个活动制作任务。
- 治愈模式退到后台仍继续制作；专注模式离开超过 3 分钟自动失败。
- 普通退出按总配方进度产生“没发好的面团”或“没烤好的面包”；失败品只能喂流浪猫。
- 使用时间券可将实际净专注时长向下匹配后再降一档，得到可出售但不进入标准图鉴的完整成品。

### 4. 数据与正式服务端边界

当前版本是交互原型，金币、库存、订单和设置使用本地演示数据。正式版不应信任客户端余额或客户端累计的计时秒数，建议拆分为以下服务：

- Identity：微信登录，以及未来 App 的手机号或 Apple 登录。
- Focus Session：唯一活动任务、绝对时间戳、暂停记录、离线恢复与结算。
- Recipe & Catalog：配方配置、版本快照与图鉴。
- Inventory：成品、礼物、购买物和猫粮篮。
- Economy Ledger：金币与时间券的不可变流水。
- Orders：零售、VIP、单次预约、周期实例与小票。
- Residents：麦子星球居民档案、偏好和随机小费。
- Market：商品购买、装备和二手回收。
- Social：邀请关系、首次专注核验和每日奖励上限。
- Notification：微信服务通知、声音与震动偏好。
- Analytics：日/周/月/年台账、每日目标和连续专注日历。

客户端使用绝对时间戳计算显示进度；恢复网络后由服务端核验开始时间、暂停日志和结束时间。开始、暂停、恢复、完成、放弃、快速出炉、购买和邀请奖励接口都应携带幂等键。

### 5. 面向 App 的迁移策略

1. 将 `domain` 模块迁移为独立 TypeScript 包，并补充单元测试。
2. 固定服务端 API 合约，微信身份只作为一种登录提供方。
3. 配方、居民、商品、台词和掉落概率采用版本化配置，不写死在页面中。
4. 动画素材与音频存放在对象存储/CDN，小程序和 App 共用资源清单。
5. App 只重写平台表现层；计时状态机、订单、库存和经济规则保持一致。

## 本地运行

1. 安装并打开微信开发者工具。
2. 选择“导入项目”。
3. 选择本仓库根目录，工具会读取 `project.config.json`。
4. 原型可使用测试 AppID `touristappid`；测试服务通知和云端能力时需替换为自己的正式 AppID。
5. 点击编译即可进入面包房首页。

当前原型不依赖 npm，也没有构建命令。

## 规则测试

仓库包含 `tests/focus-session.test.js`，覆盖真实阶段累计、配方休息、五分钟限时暂停，以及治愈/专注模式的后台差异。使用 Node.js 运行：

```bash
node tests/focus-session.test.js
```

## 原型与正式版的差异

- 计时页当前演示基础前台计时，尚未接入服务端可信时间和完整配方休息调度。
- 金币购买、订单和图鉴使用演示数据，刷新后不会形成正式云端账本。
- 微信服务通知需要正式 AppID、用户授权、订阅模板与服务端发送能力。
- 邀请、随机居民、小费、流浪猫熟悉度和装修装备目前主要完成产品定义，详见 PRD。
